Task 1 Analytical Answers:
1. Which CUDA implementation performed better?
   -> Tiled Shared-Memory CUDA consistently outperformed Basic Global Memory CUDA.
2. Did shared-memory tiling improve performance for every matrix size?
   -> Yes, especially for larger matrices (512x512 and 1024x1024) where memory traffic dominates.
3. How did the block/tile size affect execution time?
   -> Block size 32x32 provided the highest throughput on the Ampere architecture due to maximal warp occupancy.
4. Why can a GPU be slower than a CPU for small matrices?
   -> Because fixed kernel launch overhead (~5-10 microseconds) and PCIe transfer latency
      exceed the tiny compute time of small matrices on CPU caches.

Task 2 Analytical Answers:
1. Did cuBLAS outperform custom CUDA kernels?
   -> Yes. cuBLAS delivers significantly higher GFLOPS and lower execution time than our custom kernels.
2. Why might cuBLAS achieve better performance?
   -> cuBLAS utilizes expert assembly-level optimizations, register tiling, multi-stage software pipelining,
      and hardware Tensor Cores on Ampere architecture that standard C++ CUDA cannot easily express.
3. How does matrix size affect observed speedup?
   -> Speedup scales up rapidly with matrix dimension N as computation dominates fixed invocation latency.
4. Why should correctness be checked before comparing performance?
   -> An incorrect algorithm or improperly mapped memory layout might execute fast by computing nothing,
      making performance metrics meaningless without numerical validation.
5. When would you prefer cuBLAS over writing a custom CUDA kernel?
   -> Always for standard linear algebra (GEMM, GEMV, triangular solves), saving engineering effort and
      guaranteeing near-theoretical peak hardware throughput across all NVIDIA GPU architectures.

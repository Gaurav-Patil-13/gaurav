Analytical Insights:
1. Why does shared memory improve performance?
   -> It reduces global memory DRAM accesses by a factor of TILE. Elements loaded
      into fast on-chip SRAM are reused TILE times by all threads in the block.
2. Does shared memory always provide the same improvement?
   -> No, the speedup depends on tile size and arithmetic intensity. Small tiles (8)
      have lower reuse, while TILE=16/32 yield maximum occupancy and bandwidth efficiency.
3. What happens when the tile size changes?
   -> TILE=8: Low occupancy and higher synchronization frequency.
   -> TILE=16 (256 threads): Optimal occupancy and low register pressure.
   -> TILE=32 (1024 threads): Maximum thread count per block, highest throughput on Ampere.
4. What limitations does shared memory have?
   -> Capacity is strictly limited (typically 48 KB - 100 KB per SM), and careless
      stride access patterns can cause shared memory bank conflicts.
5. How does data reuse affect performance?
   -> In matrix multiplication, naive global accesses require 2*N memory loads per element.
      Tiled shared memory reduces this to 2*N/TILE loads, shifting the kernel from
      memory-bandwidth-bound closer to compute-bound.

Analytical Answers:
1. Why can atomic operations become a bottleneck?
   -> Atomic operations serialize hardware memory accesses to the same address.
      When thousands of threads update identical bins, parallel execution collapses into sequential order.
2. What happens when many threads update the same bin?
   -> Severe atomic collision and memory stall cycles degrade throughput significantly.
3. How does shared memory reduce contention?
   -> Privatization creates per-block histogram copies in low-latency SRAM.
      Contention is isolated to threads within the block, and only one commit to global memory
      occurs per block at the end.
4. What happens when the number of histogram bins increases?
   -> Collisions decrease because updates scatter across more addresses, but shared memory usage
      per block increases, potentially limiting active block occupancy if bins exceed available SRAM.
